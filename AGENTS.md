# Repository instructions

## Privacy and publishing (mandatory)

- Never publish, upload, commit, or disclose the repository owner's personal email address. This applies to source files, documentation, Git author/committer/tagger metadata, release notes, CurseForge changelogs, generated artifacts, logs, and public comments.
- Use the owner's GitHub-provided `@users.noreply.github.com` identity for commits made on their behalf. GitHub automation should use its own official noreply identity. Do not use a personal email as a fallback.
- Before creating commits or tags, check the configured identity and use a verified privacy-safe identity. Before pushing or publishing, verify the actual outgoing commit/tag metadata and changes, including generated release notes. Never print private email addresses during these checks; report only pass/fail or redacted results.
- If the identity or outgoing metadata cannot be verified, stop before publishing and ask the owner. Do not bypass GitHub's email privacy protections.
- Keep the `.pkgmeta` manual changelog configuration and release workflow privacy checks intact. Update `CHANGELOG.md` with clean, version-specific release notes for every version bump. Never fall back to autogenerated Git commit changelogs.
- Do not restore or push pre-cleanup Git history, old tags, or private backups. If historical exposure is discovered, notify the owner privately and obtain approval before any history rewrite.
- Preserve the existing automated GitHub-to-CurseForge publishing process and verify privacy-safe metadata after a push. Never trigger a release solely for documentation changes.
